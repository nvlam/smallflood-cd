# Extended engineering pilot: 15 epochs

## Material Passport

- Stage: experiment preparation; remote GPU execution not performed by assistant.
- Scope: existing proposed, FC-Siam-Diff and BIT implementations; train/validation only.
- Evidence: previous GPU smoke reproducibility and three-epoch pilot; public band mapping report.
- Change: launcher metadata/preflight and manual sequential shell wrapper only.
- Limits: no long-run reproducibility claim, no final scientific comparison or edge benchmark.

## Frozen run settings

Fresh initialization, seed 42, 15 epochs per model, batch 8, FP32, zero loader workers,
strict deterministic mode, math attention, no scheduler. Keep existing model/loss/learning-rate
configurations. Do not resume three-epoch checkpoints or regenerate prepared arrays.
Select checkpoint using event_pixel_v2 event-macro F1 at fixed probability threshold 0.5.
The legacy filename best_composite.ckpt does not imply composite scoring.
The engineering-only flag remains because this is a pilot, not because the published bands
remain unverified. Metadata checking does not inspect every raw raster or validate NPY contents.

## Manual execution

From the remote project root, after installing this update and inside tmux:

```bash
bash scripts/run_pilot15.sh
```

The wrapper checks metadata for all three configurations before any training, runs unit tests,
saves dependency/GPU information and a source snapshot, then trains sequentially.
On any failure it stops without retrying. No test loader or experiment matrix is launched.
Output: runs/pilot15/<UTC>/<UTC>_<model>; logs and source snapshot: artifacts/pilot15/<UTC>.
Each run saves resolved config, environment, timing.jsonl, metrics.jsonl, best/last checkpoints
and summary.json upon completion. Exit code zero plus ALL THREE PILOTS COMPLETE marks completion.
Detach tmux using Ctrl-b then d; do not use Ctrl-c unless intending to interrupt.

Budget: roughly 4–6 hours total from earlier three-epoch timings, conditional on GPU/I/O load;
not a measured runtime for this extended run. Check free disk and competing GPU jobs first.
After completion, review train/validation curves and object/boundary diagnostics before
deciding further runs. Do not infer final superiority from a single-seed pilot.
